## Deferred by design

The spec's written assumption: *"The one-time secret setup is performed by the
repository owner out of band. The track is complete and verifiable in the
repository without it; only the live deploy needs the secrets."*

Nothing in the repository was weakened to work around the missing secrets. The
three partial ACs (AC-1, AC-3's live half, AC-8's live half) are exactly the
ones that require a deployed site, and they are recorded as partial rather
than claimed. The first push to `main` after the secrets are added will:

1. create the Pages project if it does not exist,
2. upload `apps/client/dist`,
3. smoke-check the deployed URL, failing the run on any console error, console
   warning, or failed asset request.

**Do not close AC-8 on the strength of this document.** "A simulated deploy
failure leaves the previously deployed build reachable" is platform reasoning —
Cloudflare Pages is understood to keep the last successful deployment live until
a new upload completes — and it has never been drilled. It is marked *partial*
deliberately, in both the requirements table above and `review.md`. Round 3 of
review restated this: AC-8 must not be recorded as covered by anything in this
track. The first live failure, if one ever happens, is what settles it.

AC-1 and AC-3's live halves carry the same status for the same reason: they need
a deploy that has actually run.

## Known gaps and residuals

1. **Phase 2's workflow/config contract harnesses remain gitignored.** They live
   under `.conductor/evidence/` and provided verification for that phase, but no
   regression protection — which is exactly why Phase R1 committed a replacement:
   `scripts/deploy/workflow.test.ts` (F4) now asserts step order, the deploy
   step's `if: success()`, the absence of `${{ secrets.* }}` inside any `run:`
   body, `--frozen-lockfile`, the fork gate, `pages_build_output_dir`, and Node
   provisioning ahead of the first `bunx wrangler` call. The old harnesses are
   still on disk, gitignored and unreferenced; they are dead weight rather than a
   gap.
2. **`scripts/` is not type-checked.** `bun run check` covers the three
   workspaces (voxel, sim, client) and `scripts/` sits outside every
   `tsconfig` `include`. Biome *does* lint it (642 → 646 files). Adding
   `scripts/` to a tsconfig was outside the phase's `Touches` and was
   deliberately not done.
3. **The `bun` version differs between local and CI.** Local is 1.4.3 (canary);
   CI pins 1.4.2. Pre-existing, not introduced here, and the deploy workflow
   pins the same 1.4.2 as `ci.yml` and `nightly.yml`.
4. **One pre-existing Biome warning** at `apps/client/src/ranch.css:1429`
   (`noDescendingSpecificity`). Untouched by this track; warnings do not fail
   the gate.
