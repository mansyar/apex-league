### Save safety (NFR-4)

- Invalid v19 payloads (unknown branch, any branch on a baby including
  `"legacy"`, a wrong-species creature branch, a Hall record with an unknown id
  or a real branch from another species) make `loadGame` return `null` through
  the existing recovery path; the raw stored payload is compared before/after
  and is byte-identical.
- Import refusals use the existing `{ok:false, reason:"invalid"}` envelope; the
  live save adapter is untouched.
- `migrate` is pure and idempotent at v19 (same input twice, and migrating a
  v19 save, produce equal objects).

## Notes

- The phase is squashed into one `feat(sim)` commit on this branch (schema,
  migration, validation, records, breeding, docs, evidence, and the tightened
  validation rework).
- Branch rules: a baby is always `branch: null` (including no `"legacy"`);
  juveniles/champions accept `null`, `"legacy"`, or a real branch owned by
  their species. Hall records accept `"legacy"` for any species or a real
  branch matching the record's species. `"legacy"` is never produced by
  `createCreature` or inheritance, so a fresh career cannot acquire it.
- Rework (validation tightening, Phase 2 only): a v19 baby with
  `branch: "legacy"` is now rejected without touching the stored payload, and
  a Hall record's real branch must match its `speciesId`; new tests cover the
  legacy-on-baby refusal, a valid species-owned Hall branch, a wrong-species
  Hall branch, and legacy Hall acceptance. Migration mapping, `SAVE_VERSION`,
  and all other Phase 2 behavior are unchanged.
- Cup session slots are untouched: they carry species and stats only, so the
  migration never invents a branch for a rival.
- Hall/detail-modal display of the branch and signature remains Phase 3; the
  stored id (this phase) plus `signatureMoveOf` (Phase 1) are its inputs.
