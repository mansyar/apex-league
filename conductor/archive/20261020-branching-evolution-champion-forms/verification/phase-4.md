## Rework (same phase, after review)

Defect: `evolveCallout` printed the legacy `EVOLUTION_STAT_BOOST`/`CHAMPION_STAT_BOOST` tables for the stat clause even when the creature had earned a real branch, so a Cinder Courser juvenile was announced with `+3 HP · +2 ATK · +2 DEF · +1 SPD` instead of its own `+2 HP · +4 ATK · +1 DEF · +2 SPD`.

- `hud/copy-growth.ts`: `evolveCallout` now resolves the form with `getBranch(creature.branch ?? LEGACY_BRANCH.id) ?? LEGACY_BRANCH` and prints the boost that gate actually applied — `championBoost` for a champion, `juvenileBoost` otherwise. Because `LEGACY_BRANCH` carries the legacy tables, an unbranched or `legacy` creature keeps the exact output from before (the two golden lines are unchanged in `copy.test.ts`).
- `hud/copy.test.ts`: new exact tests `evolveCallout announces the earned branch's own juvenile leap` (`+2 HP · +4 ATK · +1 DEF · +2 SPD`, Cinder Courser) and `… champion leap` (`+5 HP · +7 ATK · +3 DEF · +2 SPD`), plus `evolveCallout keeps the legacy numbers for the old line` (`+6 HP · +4 ATK · +4 DEF · +2 SPD`, no signature claim).
- `hud/plates-creature.ts`: `paintBranchBadge` no longer prints `"Legacy — favors —"`; when the reading has no favored pair the title is the path line itself ("…no signature"), while a real branch keeps `"<Label> — favors ATK + SPD"`. `hud/plates.test.ts` asserts the legacy title has no "favors" and mentions no signature.
- Fresh counts for the exact Phase 4 command: targeted 113 pass / 388 expects; `verify` 2036 pass / 1 skip / 0 fail (2037 tests, 153 files), 7 pre-existing warnings; determinism byte-identical; build 244 modules, JS 843.12 kB.
- Migration, save schema, sim numbers and every other Phase 4 behaviour are untouched.

## Rework 2 (same phase, seeded browser check at 1400px)

Two defects, both real at runtime; the seeded check reproduced them.

**1. The plate badge truncated and squeezed the name.** `.creature-branch` was the third item in the `.creature-chips` column beside "Juvenile" and "Steady", so in the 300px plate "Cinder Courser" rendered as "CINDER COU…" and the wider chips column pushed the 19px name into "EMBER DRA…".

- `hud/plates-creature.ts`: the badge is now a `div.creature-branch` appended to the plate directly after the head row and before the stat cells, not a chip. `chips` holds exactly the stage tab and the form chip again, so the name keeps its pre-branch width. `paintBranchBadge` writes the full reading as text: `Cinder Courser · ATK + SPD`, or `Legacy` alone (no "favors —"), with the full phrase in `title`/`aria-label` and the branch hue on `--hue`. Hidden for a baby past the hinted day and on the collapsed plate.
- `ranch.css`: `.creature-branch` is a full-width block (10px, 700, uppercase, `border-left` in the branch hue, `overflow-wrap: anywhere` so a long label wraps instead of truncating), plus `[hidden]` and collapsed-plate rules. No max-width, ellipsis or nowrap remains.
- `hud/plates.test.ts`: the paint tests assert the composed text; new fake-DOM tests assert the line's place (`root.children` = head row, then the line, then the stat row) and that the chips still contain only the stage tab and form chip, plus the baby hidden case on a real built plate.

**2. The detail modal's stat breakdown showed legacy evolved numbers.** `stats.ts` `stageBoostFor(stage)` read `EVOLUTION_STAT_BOOST`/`CHAMPION_STAT_BOOST` regardless of branch, so a `cinder_courser` juvenile showed `+3/+2/+2/+1` instead of the `+2/+4/+1/+2` it earned.

- `stats.ts`: `stageBoostFor(creature)` resolves `getBranch(creature.branch ?? LEGACY_BRANCH.id) ?? LEGACY_BRANCH` and returns `juvenileBoost` for a juvenile or `juvenileBoost + championBoost` for a champion — the cumulative reading the old code produced. Because `LEGACY_BRANCH` carries the legacy tables, an unbranched or `legacy` creature is byte-identical to before.
- `stats.test.ts`: Courser juvenile `{hp:2,atk:4,def:1,spd:2}`, Courser champion `{hp:7,atk:11,def:4,spd:4}`, and a `legacy` creature `{hp:3,atk:2,def:2,spd:1}` / `{hp:9,atk:6,def:6,spd:3}`, each also checking `baseRolled` recovers the pre-evolution roll.

Scope: `packages/sim/src/stats.ts` and `packages/sim/src/stats.test.ts` were added as an approved extension for this rework; `apps/client/src/ranch.css` was already in the phase's files. Save data, migration, sim battle numbers and every other Phase 4 behaviour are untouched.
