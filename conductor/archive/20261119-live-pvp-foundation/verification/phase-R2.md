## What changed

- `apps/server/src/live/room.ts` — `ready()` now builds `MatchStart.identities`
  from `[...room.seats].sort((a, b) => a.seat - b.seat)`, restoring the invariant
  `identities[i]` is the trainer holding room seat `i`. The R1 fix frees seat 0
  but `join()` appends the reused seat, so insertion order was `[guest(1),
  third(0)]`; sides, per-seat intents and forfeits all index by room seat.
  No other behavior changed (phase transitions, ready flags, disconnect, seed,
  fixed sides).
- `apps/server/src/live/room.test.ts` — removed the masking `.sort()` calls in
  the vacated-seat test; it now asserts `seats.map(s => s.seat) === [1, 0]`,
  `seats.map(s => s.trainerId) === ["guest", "third"]` and
  `start.identities.map(i => i.trainerId) === ["third", "guest"]` (exact order).
- `apps/server/src/live/route.test.ts` — new in-memory `createLiveServer` test
  (fake sockets, fake clock, no port/timers/network): create → join → host
  disconnect → third join → both ready; asserts the bootstrap stream keys are
  `["third", "guest"]` (side 0 = seat 0 = third, side 1 = seat 1 = guest); sends
  DISTINCT triggers (`spark` from the guest socket, `flare_dart` from the third
  socket) and reads the emitted dense frame with `readFrame`, asserting the
  guest's move appears on side 1 and the third's on side 0; then disconnects the
  guest and asserts the surviving third receives exactly one `forfeit` verdict
  with `winnerSeat === 0` and the guest receives none.

## Regression proof (failing test first)

With the `.sort()` temporarily removed from `ready()`, both new assertions fail:

- `route.test.ts:415` — expected stream keys `["third", "guest"]`, received
  `["guest", "third"]`.

With the fix restored, both pass. The route test is a genuine end-to-end
assertion through the real room registry, loop and adapter core — no pure-helper
substitute was needed.
