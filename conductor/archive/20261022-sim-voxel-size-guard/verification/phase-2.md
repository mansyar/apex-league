seam it already had, using the repo's own house precedent — `packages/sim/src/cup.ts`
(barrel) + `packages/sim/src/cup/*` from the `cup_module_refactor_20261018` track.
`moduleResolution` is `"bundler"`, so a file and a same-named folder coexist and
the **file** wins for a bare import: `./legacy`, `./breeding`, `./clock`,
`./cup/session` and `./save/validators` still resolve to the barrel, and every
consumer import path is untouched.

## Notes

  `retireeRecord` from `legacy`. The split keeps the direction one-way —
  `breeding/pairing.ts` and `breeding/drift.ts` import the *submodules*
  (`../legacy/lineage`), never the `legacy` barrel, so no cycle is possible.
