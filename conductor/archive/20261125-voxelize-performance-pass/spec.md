# Voxelize Performance Pass — Specification

> Requirements are stable. Once an `FR`, `NFR`, or `AC` ID is approved, do not
> renumber it. If a requirement is removed, mark it `Withdrawn` instead of
> deleting it.

## Overview

Deliver a measured, deterministic performance improvement to the shared voxelize
and greedy-mesher pipeline. The track establishes a repeatable baseline, profiles
the real bottleneck, applies only evidence-driven optimizations, and proves that
all generated creature artifacts remain byte-identical. It also records the new
performance baseline in the technology stack documentation.

## Problem / Motivation

The deterministic voxel pipeline is a structural cost center for local and CI
verification. The current `voxelize()` implementation samples a resolution³ grid,
allocates a point object per cell, and evaluates part SDFs in paint order until a
part claims the cell. The mesher then performs additional full-grid scans and
per-face work. Earlier test-suite work reduced fuzz seed counts and parallelized
suites, but explicitly left a dedicated voxelize-performance follow-up because
per-seed CPU cost remained the floor.

The roster and test surface have grown since that work. Repeated full verification
now consumes substantial developer and CI time, while the historical sub-10s goal
is no longer a realistic absolute target. A focused pipeline pass can improve
feedback time without changing creature appearance, generated bytes, game logic,
or balance.

## Goals & Success Metrics

- **Goal:** reduce voxel-pipeline wall time through measured, semantics-preserving
  optimization.
- **Median benchmark:** reduce median `voxelize()` wall time by at least **20%**
  across the fixed 21-archetype × 3-stage, seed-42 corpus.
- **Package gate:** reduce the capped voxel-package test command wall time by at
  least **15%** on the same machine and command.
- **Correctness:** preserve every voxel grid, mesh, committed creature GLB,
  manifest, prop digest, and deterministic artifact hash.
- **Safety:** introduce no dependency, quality, resolution, schema, API, or
  deployment change.

## Scope

### In Scope

- A deterministic benchmark harness for the fixed 63-generation corpus.
- Baseline timing and profiling evidence for `voxelize()` and `meshGrid()`.
- Focused changes to `packages/voxel/src/voxelizer.ts`, `sdf.ts`, `mesher.ts`,
  `ao.ts`, and directly related tests or benchmark utilities.
- Allocation reduction, loop restructuring, precomputation, bounding rejection,
  and other semantics-preserving pipeline optimizations supported by profiling.
- Bounded caches, memoization, or workers only when they are deterministic,
  concurrency-safe, memory-bounded, and demonstrably beneficial end to end.
- Regression tests proving semantic and byte identity.
- A dated `conductor/tech-stack.md` note with the measured before/after result.

### Out of Scope

- Archetype anatomy, species data, stage scaling, grid resolutions, SDF shapes
  authored by individual creatures, palettes, pivots, rigs, or GLB format changes.
- Regenerating or editing committed GLBs, manifests, prop artifacts, or baselines.
- Changes to `apps/`, `packages/sim/`, server code, save schema, APIs, deployment,
  or gameplay.
- New dependencies, package-manifest changes, CI policy changes, or test-framework
  changes.
- Lowering test coverage, skipping assertions, widening budgets, or re-baselining
  existing expected output to hide a regression.
- Unrelated refactors outside the measured bottleneck.

## Edge Cases

- **Timing noise or co-running load:** record machine/load context, use repeated
  medians, and repeat only the benchmark when noise threatens confidence. Do not
  claim a target from a single run.
- **Worker startup overhead:** evaluate total corpus and package-gate time, not
  isolated compute time; reject workers if startup or orchestration erases the
  gain.
- **Cache correctness:** exercise alternating archetypes, seeds, stages, and
  concurrent calls so stale or cross-contaminated entries cannot pass unnoticed.
- **Memory growth:** any cache has an explicit entry/byte bound and a documented
  lifetime; repeated mixed-input runs must not grow without limit.
- **Semantic drift:** any voxel, class, mesh, GLB, manifest, or prop digest change
  is a failure even if timing improves.
- **Target not met:** after a bounded, profiling-driven optimization effort, stop
  and report blocked rather than weakening coverage, changing output, or moving
  the target.
- **Load-induced test timeout:** follow the workflow fallback ladder and isolate
  the named test once under low load; do not repeatedly rerun the full suite to
  manufacture a pass.

## Open Questions & Assumptions

- **Assumption:** before/after measurements run on the same development machine,
  Bun 1.4.4, fixed corpus, and comparable background load.
- **Assumption:** the historical sub-10s whole-suite aspiration is superseded by
  the approved relative targets for the current 21-species roster.
- **Assumption:** safe caches or workers are permitted inside the selected
  pipeline boundary, but only when profiling and end-to-end measurements justify
  their complexity.
